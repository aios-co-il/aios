# הסדנה של כרמן: תכנית בנייה מלאה

מסמך תכנון. כל יכולת של מחלקת השיווק עוברת דרך כרמן. המשתמש כותב מה הוא רוצה, כרמן בוחרת סוג, גודל, סגנון, מנוע וסקין, ומציגה את התוצאה בלוח. אין טפסים והגדרות.

הסקר שמאחורי המסמך נעשה על הקוד בענף `cursor/carmen-workshop-shell-ab0e`. נתיבי הקבצים מדויקים.

## 1. עקרונות

1. **משפט אחד מספיק.** "סרטון קצר של כרמן ליד מחשב" מפעיל את כל השרשרת. כרמן שואלת שאלה אחת לכל היותר, רק על דבר שאי אפשר להסיק: מי הלקוח, או נכס חסר כמו לוגו.
2. **ההגדרות הן של כרמן.** סוג הפרויקט, הפורמט, הסגנון הוויזואלי, מודל התמונה, מנוע ההנפשה, אורך הסצנות, קול הקריינות: כולם מוסקים מהבקשה, מהלקוח ומהערוץ. המשתמש יכול לשנות כל אחד מהם בצ׳אט ("תעשי את זה אנכי").
3. **כסף עובר אישור אחד, בצ׳אט.** כרמן מציגה תוכנית עם עלות כוללת וכפתור "אשר". אחרי אישור שרשרת ההפקה רצה עד הסוף בלי עוד שאלות. פעולות חינמיות לא מבקשות אישור.
4. **כל תוצר הוא עמוד בלוח.** הוא מופיע במרכז, גדול. וריאציות וחומר נלווה נערמים מתחתיו והלוח גולל אליהם, כמו הצ׳אט.
5. **כל תוצר שייך לפרויקט ולתיקייה.** קופי, תמונות, וידאו (סצנות, סרט סופי, קריינות, מוזיקה, רפרנסים).
6. **אין בניה מקבילה.** הכלים החדשים עוטפים את הלוגיקה הקיימת (RPC, פונקציות Edge, ורקר). מסך הקריאייטיב הקיים נשאר כגיבוי ולא נמחק.
7. **לא מתערבים בפרודקשן.** הכול מתפתח ונבדק ב־Preview מול Staging, ושום הודעת וואטסאפ ישנה לא נשלחת מחדש.

### 2.2 מה לכרמן יש היום

- **כלי נתונים לסטודיו** (`supabase/functions/_shared/creative-studio-tools.ts`): `get_studio_state`, `update_studio_settings`, `attach_to_project`, `edit_scene`, `add_scene`, `delete_scene`.
- **פעולות בתשלום** עוברות רק דרך `studio_ui_action`. הכלי מחזיר הוראה לדפדפן, והדפדפן מפעיל את אותם handlers של הכפתורים. כלומר היצירה בפועל תלויה במסך סטודיו פתוח.
- **וידאו:** `get_video_storyboard`, `render_video_film` (`video-director-tools.ts`).
- **צינור:** `list/get/create/handoff/update_marketing_work_item`.
- **תמונה:** `generate_ad_image` (OpenAI בלבד, חייב מפתח OpenAI) ו־`create_social_post`.
- **סקינים:** `copywriter`, `creative_direct`, `creative_studio`, `video_director`, `seo`. הסקין `creative_studio` ננעל בסטודיו עם `task_skills`, ובסדנה לא מופעל בכלל.
- **ורקר:** `clip`, `voice`, `music`, `render`, `reference_analysis`. סוג `still` מוגדר במסד אבל לא ממומש. תמונות סצנה נוצרות מהדפדפן דרך `ai-generate-social-image`.

### 2.3 למה הסדנה לא עובדת עם כרמן היום

1. הצ׳אט של הסדנה (`CarmenChatBar.tsx`) שולח הקשר של "תיקון מערכת". הוא לא שולח `item_id`, ולא סקין `creative_studio`.
2. הצ׳אט לא מטפל באירועי `ui_action`, `tool_result` ו־`status`, ולכן פעולה בתשלום לא מתבצעת.
3. אין כלי שיוצר פרויקט מבקשה חופשית. "פרויקט חדש" בסדנה לא יוצר שורה במסד.
4. הלוח הוא גרף של שלבים (React Flow) ולא עמודי תוצרים. אין Realtime, ולכן הוא לא מתעדכן.
5. צריך לשים לב: מסך הקופי נעול ב־`pin_skills_only` בלי כלים, ולכן קופי לא נכנס לשרשרת אוטומטית.

## 3. הארכיטקטורה

```
משתמש כותב בצ׳אט (סרגל כרמן, צד ימין)
   │  context: workshop { project_id, selected_artifact_id, client_id }
   ▼
run-ai-agent  ── נתב כוונות ── בוחר סקין (copywriter / creative_studio / video_director)
   │                         └─ שולח אירוע SSE: skin  (האווטר מתחלף)
   ▼
workshop-tools  (_shared/workshop-tools.ts, כלים מבוססי כוונה, בלי תלות בדפדפן)
   ├─ workshop-defaults  (פונקציות טהורות: ערוץ→פורמט, סוג, סגנון, מספר סצנות, מדיניות עלות)
   ├─ ai-generate-social-image / marketing-copy-plan / marketing-creative-plan (קיימים)
   ├─ RPC: save_video_storyboard, produce_video, queue_video_* (קיימים)
   └─ כותב workshop_artifacts + marketing_runs
   ▼
Realtime  →  הלוח מוסיף עמוד חדש וגולל אליו  +  הצ׳אט מציג כרטיס קטן עם תמונה ממוזערת
   ▼
ורקר (דרופלט): still (חדש), clip, voice, music, render  →  מעדכן artifacts
```

## 4. הפרונט

### 4.1 הלוח (מחליף את React Flow)

- **פיד אנכי** של עמודים. כל סוג תוצר מקבל רכיב: כרטיס קונספט, בלוק קופי, עמוד תמונה (עם וריאציות וגדלים כצ׳יפים), פס סצנות, נגן וידאו, נגן אודיו, רפרנס.
- **עמוד חדש = גלילה אוטומטית.** מתג "עקוב אחרי כרמן". המשתמש יכול לעצור את הגלילה.
- **לחיצה על עמוד** בוחרת אותו כהקשר: "שני את זה" בצ׳אט יחול על העמוד הנבחר.
- **עמודי טעינה:** כשהפקה רצה, הלוח מציג שלד עם סטטוס ועלות, מתוך `marketing_runs` ב־Realtime.
- **פעולות על עמוד:** אישור, הורדה, העתקה, שליחה לקמפיינים. כל אלה גם בצ׳אט.
- **תיקיות:** עץ לפרויקט (קופי, תמונות, וידאו: סצנות, סרט סופי, קריינות, מוזיקה, רפרנסים). נגזר מ־`folder` ב־`workshop_artifacts`.
- **מובייל:** הלוח למעלה והצ׳אט למטה, כפי שקיים היום. הלוח הופך לעמוד אחד בכל פעם.

### 4.2 גשר הצ׳אט

1. הסרגל ב־`CarmenChatBar.tsx` שולח `workshop_context` (`project_id`, `selected_artifact_id`, `client_id`) כשהנתיב הוא `/workshop`. השרת מזהה אותו ומפעיל `task_mode: "workshop"`.
2. שלושה אירועי SSE חדשים בסרגל: `artifact` (כרטיס עם תמונה ממוזערת בצ׳אט, לחיצה גוללת בלוח), `skin` (החלפת אווטר ושם), `status` (שורת התקדמות).
3. כרטיס אישור עלות בצ׳אט (הלוגיקה של `needsChatApproval` ב־`studioChat.ts` כבר קיימת, מועברת לשימוש משותף).
4. העלאת קבצים בצ׳אט: הסרגל מעלה ל־`command-center-files`, והכלי `workshop_attach` מסווג וממקם בפרויקט, בלי שהמשתמש יבחר תפקיד.
5. תוויות כלים בעברית במקום שם הכלי (`TOOL_LABELS` מתוך `CreativeStudioChat.tsx`).

### 4.3 סקינים בבחירה אוטומטית

- נתב כוונות בצד השרת בוחר לפי ההודעה והמצב: קונספטים וקופי = `copywriter`, תמונה וסטטי = `creative_studio`, סרט = `video_director`, SEO = `seo`.
- בסדנה כל הסקינים של השיווק מקבלים את כלי `workshop_*` (מיגרציה על `ai_skills`).
- אירוע `skin` מחליף את האווטר בזמן אמת, במקום בורר ידני. הבורר הידני נשאר לעקיפה.

## 5. מסד נתונים

מיגרציה אחת: `workshop_artifacts`

| עמודה | תיאור |
| --- | --- |
| `id`, `tenant_id`, `item_id` | זהות והשיוך לפרויקט |
| `kind` | `concept`, `copy`, `image`, `variation`, `storyboard`, `scene_still`, `clip`, `narration`, `music`, `film`, `reference`, `article` |
| `folder` | נתיב לוגי: `copy`, `images`, `video/scenes`, `video/film`, `video/narration`, `video/music`, `references` |
| `ref_table`, `ref_id` | הקישור לנכס, לווריאציה או לסצנה הקיימים (לא מעתיקים נתונים) |
| `title`, `url`, `thumb_url`, `meta` | תצוגה |
| `status` | `pending`, `ready`, `failed`, `approved` |
| `position`, `created_at` | סדר בפיד |

RLS לפי `tenant_id`. Realtime מופעל על הטבלה. אין מיגרציה של נתונים ישנים: פרויקטים קיימים מקבלים תצוגה נגזרת מ־`payload` עד שנוצר בהם תוצר חדש.

## 7. בדיקות וקבלה

- **בדיקות יחידה:** `workshop-defaults` (כל כללי ההסקה), מנתח כוונות, הלוגיקה של כרטיס האישור, ורקר `still` (כמו `render-worker/test/*`).
- **סט הערכה (שלב 6):** 15 בקשות בעברית ("סרטון של כרמן ליד מחשב", "מודעה לסטורי ולפיד", "שני את הרקע", "הוסיפי מוזיקה שקטה") מול `run-ai-agent` עם ספקים מדומים. בודקים רצף כלים, ושאין שאלות מיותרות.
- **קבלה לכל שלב:** המשתמש כותב משפט אחד בסדנה ב־Preview ומקבל את התוצר, בלי למלא שדה. הוורקר רץ מול Staging בלבד.
- **פריסה:** שינוי תחת `supabase/` מקבל סביבת Supabase Preview נפרדת לכל PR (`docs/agents/db-deploys.md`). בשלב 0 נבדק שהפונקציות החדשות מוכרזות ב־`supabase/config.toml` ושה־Preview מול Staging פועל.
